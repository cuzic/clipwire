# 見送り・再開待ちバックログ

## クリップボード履歴

- 見送りの理由: `AddClipboardFormatListener` は HWND とメッセージポンプを必要とし、現行 STA ループの作り直しが要る。変更ごとの `OpenClipboard` は他アプリのエラーや遅延レンダリングを誘発しうる。また、機微データを扱うため除外フォーマットの尊重、メモリのみの保持、認証必須といった条件が必要。
- 再開条件: `GetClipboardSequenceNumber` の別スレッドでのポーリングを採用し、メモリのみ・テキストのみ・既定無効・トークン必須・`--allow-no-token` 併用禁止を満たす設計を再検討する。
- 関連 ADR: ADR-0008 §「クリップボード履歴(Deferred)」。

## TTL（「1 時間だけ承認」）

- 見送りの理由: 承認疲れを増やし、盲目承認を助長する。
- 再開条件: 必要になった場合に別 ADR を作成する。
- 関連 ADR: ADR-0006 §「見送り(Deferred)」。

## Rhai `env`

- 見送りの理由: 必要な値は承認対象の `env` 宣言で渡せる。名前ベースのブロックリストは `*_PAT` や `DATABASE_URL` などの漏えいを防ぐ境界にならない。
- 再開条件: ADR 記載なし。
- 関連 ADR: ADR-0007 §「採用しない」。

## Rhai `retry`

- 見送りの理由: `loop`、`run_ok`、`sleep` で記述でき、`NativeCallContext` の実装コストに見合わない。
- 再開条件: ADR 記載なし。
- 関連 ADR: ADR-0007 §「採用しない」。

## Rhai `wait_port`

- 見送りの理由: `run(["powershell", ...])` で記述できる。
- 再開条件: 必要が出たときに再検討する。
- 関連 ADR: ADR-0007 §「採用しない」。

## Rhai `read_text`

- 見送りの理由: `dir` 相対の単純な join だけの関数を作る価値が薄く、canonicalize や `\\?\` 比較に実装上の罠がある。
- 再開条件: 必要が出たときに再検討する。
- 関連 ADR: ADR-0007 §「採用しない」。

## `concurrency = "queue"`

- 見送りの理由: TTL 切れ、再 register、サーバ再起動との相互作用が未定義であり、個人用途では `reject` / `allow` で足りる。
- 再開条件: 上記の相互作用を定義し、`reject` / `allow` では不足する利用要件が生じること。
- 関連 ADR: ADR-0002 §5、§「Alternatives considered」。

## params の `pattern`

- 見送りの理由: 初版では提供しない。部分一致や既定パターンの穴という実装上の罠があり、`choices` のみなら regex crate の追加も避けられる。
- 再開条件: 自由入力が必要になった時点で ADR を更新し、全体一致、危険なパス・先頭 `-` の拒否、承認 UI での可視化を必須にする。
- 関連 ADR: ADR-0004 §4、Consequences。

## params（運用モード (A)）

- 見送りの理由: 実運用の自動承認モードでは、新しいターゲットを作れば足りるため価値が低い。
- 再開条件: 手動承認モード (B) へ移行する場合に前倒しする。
- 関連 ADR: ADR-0004（Status: Deferred）、ADR-0006。

## 手動承認 UI（Phase 5b）

- 見送りの理由: 実運用は `--auto-approve` であり、2 段階 toast・レビュー画面は手動承認モード専用で使われない。
- 再開条件: 手動承認モードを使う判断をした時点。ただし使い捨てターゲットが大量にあるため、使い捨て実行の代替設計も必要。
- 関連 ADR: ADR-0006 §「適用範囲」、Consequences。

## Tailscale IP 変化時の bind のやり直し

- 見送りの理由: 既存の `serve_forever` の別課題として扱うことだけが記載されている（それ以上の理由は ADR 記載なし）。
- 再開条件: ADR 記載なし。
- 関連 ADR: ADR-0011 §B-8。

## 使い捨てターゲットの棚卸し・削除（T8.2）

- 見送りの理由: リリース時の既存ターゲット移行点検として T8.2 に割り当てられている（それ以上の理由は ADR 記載なし）。
- 再開条件: T8.2 で、古いものから削除する手順、`registered` と `approved/` の掃除、Linux 側 `targets.toml` の整理方針を決めて実施する。
- 関連 ADR: ADR-0010 §4b（`approved/` の増加）。棚卸し・削除自体は ADR 記載なし。
