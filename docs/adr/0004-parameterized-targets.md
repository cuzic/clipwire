# ADR-0004: パラメータ付きターゲット

- Status: **Deferred**(運用モードが自動承認のため価値が低い。手動承認モードへ移行する場合に再開。内容は改訂済み: 初版は `choices` のみ)
- Date: 2026-09-30
- Depends on: ADR-0010(宣言を承認対象に含める), ADR-0006(承認 UI)

## Context

ターゲットは固定内容で、ブランチ等を変えたいときは別ターゲットを作るしかない。しかし承認モデルは「人間が承認した内容のみ実行できる」であり、実行時に任意文字列を差し込めると承認が無意味になる。

## Decision

1. **宣言的パラメータ**を定義する。宣言は承認対象(ADR-0010 の正規形)。
   ```toml
   [targets.awase-build.params.branch]
   choices = ["main", "dev", "release"]   # 初版はこれのみ
   default = "main"                       # choices に含まれること
   ```
2. 実行: `clipwire exec awase-build --arg branch=dev`。リクエストは `{"name":..., "args":{"branch":"dev"}}`。`args` はサーバが未対応の場合(ADR-0010 の feature チェック)は送信前にエラー。
3. **サーバ側検証**: 宣言にない引数名は 400。値は `choices` のいずれかと**完全一致**しなければ 400。必須引数(`default` なし)が欠けたら 400。改行・NUL・制御文字は拒否。
4. **regex(`pattern`)は初版では提供しない**。将来導入する場合は、次を必須条件とする: 常に `^(?:…)$` で包み全体一致にする(部分一致で何でも通る事故を防ぐ)、既定パターンは「先頭が英数字、`.` 単独・`..` を含まない、先頭 `-` 不可」とする(`git checkout .` や `../` によるパス脱出を防ぐ)、承認 UI でパターンを可視化する。
5. **適用範囲**:
   - Rhai: `params` 宣言があるターゲットに限り、`args`(`Map<String,String>`)を注入する。宣言のないターゲットには注入しない(既存スクリプトの `let args = ...` をシャドウしないため)。`run([..., args.branch])` のように argv の**1 要素**として渡す。`run` はシェルを介さない。
   - Steps: `params` 宣言があるターゲットに限り、argv 要素内の `${name}` を置換する。宣言がないターゲットの `${...}` はリテラルのまま残す(既存 steps を壊さない)。`StepsDef::Text`(shlex 分割)は**分割後**に置換し、値によるトークン分割を起こさない。
   - 値は `env` や `dir` には入れない(承認された定義の外から環境や CWD を変えられないように)。
   - `cmd /c`、`powershell -Command`、`sh -c` のように引数を再解釈するコマンドへ `args.*` を渡すのは、`choices` の範囲でも危険になりうる(選択肢の値自体が安全であることを承認者が確認する)。
6. 監査ログ(ADR-0003)に引数の実値を記録する。

## Consequences

- 承認済みの「形」の内側でのみ可変になり、信頼境界を保てる。`choices` のみの初版は、regex の実装罠(部分一致、既定パターンの穴)と `regex` crate の追加を避けられる。
- 自由入力(任意のブランチ名など)は初版では扱えない。必要になった時点で本 ADR を更新して `pattern` を導入する。
- 既存ターゲットは影響を受けない。

## Alternatives considered

- **`exec <name> -- <extra argv>`**: 承認内容の外から任意引数を渡せ、`git -c core.sshCommand=...` のような引数経由の任意コード実行が可能になるため却下。
- **環境変数で渡す**: 検証境界が曖昧になる。
- **最初から regex**: 上記の罠があるため後回し。
